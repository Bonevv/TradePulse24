# Общи цени през Cloudflare

Cloudflare обновява цените на едно място. Сайтът, графиките и Лабораторията четат запазените данни; отварянето на страницата не изпраща заявка към Tiingo или Twelve Data. Обновяването продължава и при затворен сайт.

**Tiingo остава основен, Twelve Data — резервен.** Ключовете са в твоя Cloudflare профил. На PHP хостинга не е нужен Node.js. GitHub съхранява кода; задачите по график се изпълняват в Cloudflare.

## 1. Създай място за данните

Влез в [Cloudflare](https://dash.cloudflare.com/) и отвори **Storage & databases → KV**. Създай namespace, например `tradepulse24-feed`, и копирай неговото **ID**. Това е идентификатор, не API ключ.

Нужен е и един SQLite Durable Object. Той се създава при публикуването по конфигурацията в `cloudflare/wrangler.jsonc`; няма отделна база за настройване. Координаторът пази графика и броячите на заявките, а KV — историята и общия пакет за сайта. Използват се услуги, налични в безплатния план. При достигане на квота обновяването може да спре.

## 2. Публикувай Worker от GitHub

От **Workers & Pages → Create → Import a repository** свържи `Bonevv/TradePulse24`, клон `main`. В настройките за изграждане задай:

| Настройка | Стойност |
|---|---|
| Име | `tradepulse24-feed` |
| Root directory | `cloudflare` |
| Build command | `npm ci` |
| Deploy command | `npm run deploy` |
| Build variable `FEED_KV_ID` | ID на създадения KV namespace |

Ако панелът показва preview deploy command, използвай същата команда само за производствения клон; не включвай отделни preview Workers с ценовите ключове. Първото публикуване може да поиска да активираш Workers или безплатните Durable Objects.

Cloudflare използва Node.js при изграждането. Той не се инсталира на PHP хостинга. Генерираният `wrangler.deploy.json` не влиза в Git и не съдържа ключове.

След публикуване ще получиш адрес от вида:

```text
https://tradepulse24-feed.ТВОЯТ-ПРОФИЛ.workers.dev
```

В Worker **Settings → Variables and Secrets** добави **Secret** `FEED_ADMIN_TOKEN`: случайна парола от поне 24 знака. Запази я при себе си. Тя служи за управлението на общите данни и е отделна от паролата за Лабораторията. Потвърди публикуването на настройките. Ценовите ключове добави в стъпка 5.

В `wrangler.jsonc` е зададено `ALLOWED_ORIGINS = https://test-systems.gt.tc`. Ако използваш друг домейн, смени стойността в този файл преди следващото публикуване. За няколко сайта изреди точните адреси, разделени със запетая, например `https://site.bg,https://www.site.bg`. Без път, `#` или крайна наклонена черта. Това разрешава четене от браузъра; публичните цени остават достъпни по URL.

## 3. Зареди началната история

Отвори адреса на Worker с **`/admin`** накрая. Въведи `FEED_ADMIN_TOKEN` и натисни **„Провери състоянието“**, после **„Зареди началната история“**. Изчакай отговор с `ok: true` и провери, че `seeded` е `true`.

Първоначално се копират 24-те ценови файла от фиксирана версия на това хранилище. Това е историята, включена в проекта, а не архив от твоя хостинг. Ако имаш по-нова или собствена история, запази нейно копие; тя не се внася автоматично в Cloudflare. Повторното зареждане не подменя вече създадените архиви. Пропускът след последните свещи се догонва при следващите обновявания на части до 30 дни.

Тази стъпка не ползва ценовите API. Историческите свещи не се представят като текущи котировки. Докато няма първо успешно обновяване, активни сигнали няма да се показват.

## 4. Свържи съществуващия сайт

Направи резервно копие и качи [пакета за обновяване до 5.3](updating.md). В съществуващия масив на `api/config.local.php` добави:

```php
'cloudflare_feed_url' => 'https://tradepulse24-feed.ТВОЯТ-ПРОФИЛ.workers.dev',
```

Ползвай само основния HTTPS адрес, без `/snapshot` или `/admin`. Друг вариант е променлива в средата на PHP `CLOUDFLARE_FEED_URL` със същата стойност.

**Запази останалите полета в конфигурацията.** `tiingo_key` и `twelvedata_key` продължават да се поддържат за досегашния PHP режим. Когато `cloudflare_feed_url` е попълнено, PHP cron не използва тези ключове — чете общия кеш. Дори `force=1` не включва местно теглене. При отказ на Cloudflare също няма скрито превключване към местните API.

Ако имаш няколко копия на сайта, обнови и свържи всяко от тях, преди да включиш ценовите ключове в Worker. Стара инсталация със собствена cron задача продължава да прави отделни заявки.

## 5. Добави и двата ценови ключа

В **Worker → Settings → Variables and Secrets** добави като **Secrets**:

| Secret | Роля |
|---|---|
| `TIINGO_API_KEY` | Основен източник на 15-минутни цени |
| `TWELVEDATA_API_KEY` | Резервни цени и дневни свещи |
| `FEED_ADMIN_TOKEN` | Вече добавената парола за `/admin` |

Не ги поставяй като build variables, в GitHub или в `wrangler.jsonc`. Публикувай промените. Достатъчен е и един ценови ключ, но с двата има резерв.

От `/admin` натисни **„Обнови по графика“**. Провери състоянието, после отвори **`/snapshot`**: трябва да има `meta.quotes` с осем инструмента и реални времена. При току-що изпълнен цикъл бутонът изчаква следващия срок; не заобикаля лимитите. При дълъг пропуск догонването може да изисква няколко цикъла.

Отвори PHP сайта с Ctrl+F5. Провери часа на цените, графика с по-стара история и зареждането на историята в Лабораторията. Пулс също чете новините и котировките от общия кеш; неговият Groq ключ остава на PHP сървъра.

## Как продължава обновяването

Cron Trigger е зададен за минути **02, 17, 32 и 47** на всеки час. Вътрешният график разрешава ценово обновяване през 15 минути от 07:00 до 22:00 по Europe/Sofia и през 3 часа нощем. При затворен пазар има едно последно обновяване. Преминаването към лятно/зимно време се отчита по Ню Йорк. Промените в Cron Triggers може да се разпространяват до 15 минути.

Календарът се проверява най-много веднъж на час. Свещите, графиките и тестовете идват от една история. H1 се записва само с четири завършени M15 свещи. Когато липсва дневен отговор, нов D1 може да се сглоби само с всички очаквани пазарни часове; наличната стара D1 история се запазва.

Страниците `/snapshot` и `/history/EURUSD` са само за четене. Десет или сто посетители не увеличават броя заявки към доставчиците. Браузърът проверява за промени през 5 минути; Cloudflare и браузърът използват кеш и ETag. Публичните данни може да изостанат с около минута заради разпространението на кеша.

Досегашната PHP cron задача може да остане за синхронизиране на локалните JSON файлове от Cloudflare. Тя вече не управлява ценовите API. Дори да я спреш, браузърът чете общите данни директно; местните архиви тогава няма да се допълват. Отварянето на сайта не замества Cron Trigger.

Сигналите продължават да се смятат в браузъра. Журналът и известията за сигнали изискват отворен сайт, както досега.

## Квоти и откази

И този вариант има ограничения. По зададения график Tiingo е ограничен допълнително до 45 заявки на час и 900 на ден, Twelve Data — до 6 в минута и 750 на ден. Броячите са общи и остават след рестартиране. При отказ се използва резервът; при изчерпани квоти се изчаква. Други програми със същите ключове също харчат квотата на акаунта.

Workers Free допуска 100 000 HTTP заявки дневно. KV Free има 100 000 четения и 1 000 записа дневно. Един пълен цикъл записва осем архива и един общ пакет; дори при 96 ценови цикъла плюс 24 календара това са до 888 записа, без първоначалния внос. Реалният дневен/нощен график прави по-малко. Допълнителни ръчни операции, други Workers и посещенията също използват квоти. Провери актуалните условия на [Workers](https://developers.cloudflare.com/workers/platform/limits/), [KV](https://developers.cloudflare.com/kv/platform/limits/) и [Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/).

При проблем отвореният сайт запазва последния получен пакет с оригиналните времена. Нов посетител без достъп до пакета вижда историята на стратегиите без активни сигнали. Предупрежденията за стари цени остават; имената на ценовите доставчици и подробните откази са само в административната проверка.

Кеширането не променя правата за разпространение на котировки. Провери дали плановете на доставчиците позволяват начина, по който публикуваш данните.

## Публикуване от компютър вместо през GitHub

За тази стъпка Node.js 22+ е нужен само на компютъра за публикуване:

```sh
cd cloudflare
npm ci
npx wrangler login
npx wrangler kv namespace create FEED
```

Копирай върнатото ID в полето `kv_namespaces[0].id` на `wrangler.jsonc` или задай `FEED_KV_ID` в средата на тази команда. После:

```sh
npm run deploy
npx wrangler secret put FEED_ADMIN_TOKEN --config wrangler.deploy.json
```

Продължи със стъпки 3 и 4. След тях въведи ценовите ключове в подканите, които командите отварят:

```sh
npx wrangler secret put TIINGO_API_KEY --config wrangler.deploy.json
npx wrangler secret put TWELVEDATA_API_KEY --config wrangler.deploy.json
```

## Ако не тръгне

- Грешка за `FEED_KV_ID` при публикуване: сложи ID на namespace като build variable, не името му.
- `seeded: false`: изпълни „Зареди началната история“. При частично завършил внос можеш да повториш.
- `needs_keys: true`: няма ценови ключ в runtime Secrets. Build variables не са достатъчни.
- `/snapshot` се отваря, но сайтът не го чете: провери точния домейн в `ALLOWED_ORIGINS` и `cloudflare_feed_url`.
- Котировките остават стари: провери последния опит и паузите в `/admin`, както и **Settings → Triggers → Cron Triggers**. Не сменяй часовете на цените ръчно.

За връщане към досегашния PHP режим изпразни `cloudflare_feed_url`, спри Cron Trigger на Worker и възстанови PHP cron задачата. Това не изтрива ценовата история или собствените резултати.
