# Работа по TradePulse24

PHP 7.4+ с cURL и Apache 2.4 са достатъчни за сайта. Препоръчва се PHP 8.x. Няма Composer или npm зависимости. Node.js се използва само за проверките при разработка; на хостинга не е нужен.

## Настройки

Копирай `api/config.example.php` като `api/config.php`. Подай личните настройки чрез средата на PHP или `api/config.local.php`. Локалните файлове са изключени от Git; не ги добавяй с `git add -f`.

В подготвената облачна среда PHP и Apache са в `/workspace/.tradepulse24-env/bin`. Стартирането е:

```sh
bash /workspace/.tradepulse24-env/start.sh
```

Средата е изолирана. Работи в съществуващото копие на проекта; нов worktree не е нужен.

## Проверки

От корена на проекта:

```sh
node tests/smoke.js
node tests/engine-smoke.js
node tests/risk-guidance.js
node tests/workflow.js
php tests/backend.php
php tests/puls.php
node tests/book-candidates.js
node tests/pair-selection.js
node tests/calendar.js
node tests/revisions.js
node tests/session-candidates.js
node tests/observation-risk-costs.js
php tests/maintenance.php
php tests/login.php
node tests/entry.js
node tests/chart.js
node tests/chart-context.js
php tests/prices.php
python tests/release.py
```

Първите три пазят наличните стратегии, следенето и ориентирите 1R/2R. `workflow.js` проверява двата стила, личните чернови, изричното публикуване, обясненията за новините и целостта на дневника. `backend.php` проверява версии, архивиране на старите правила, отхвърляне на остарели резултати и валидиране на времевите интервали.

При промяна на кандидатите или индикаторите пусни и:

```sh
node tests/candidates.js
```

Проверката пуска първоначалните 18 изследователски варианта върху включената история с отделен хронологичен период и проверява, че KAMA, DeMarker и RVI не използват бъдещи свещи. `book-candidates.js` проверява новите девет комбинации, абсолютните стопове при гап, изчакването преди активиране и неизменността на приключилите сделки при добавяне на бъдещи данни. `puls.php` използва примерен транспорт за реалната операция за генериране, автоматичен избор на модел, ограниченията на контекста, кеша и лимитите; не изразходва външна квота.

`revisions.js` проверява всичките 31 преработки спрямо оригиналите, оценките по инструмент, липсата на бъдещи данни, дневния край, изтекли поръчки и равенството на кешираните Ишимоку линии. `pair-selection.js` покрива положителен общ резултат с губещ последен период, разходи, малки извадки, стари данни и таблицата на EMA 20/50/200 D1. Нито един тест не преименува предварителна преработка на потвърдена „Силна“.

При налични Python Playwright, Chromium и подготвения Apache runtime:

```sh
python tests/browser.py
python tests/workspace.py
```

Тестът създава временно копие на сайта и отделен Apache на порт 8081. Не копира локалните конфигурации. Проверява входа, черновите, истинския Web Worker, версии, публикуване, дневника, въпросите и последващия разговор, избор на посока, общия дневен обзор, безопасното показване на отговорите, защитата на PHP файловете и мобилния изглед. След края почиства своя процес и временните файлове.

Тестовете не извикват външни услуги и не променят оригиналната история. Обновяването с Twelve Data се проверява отделно със собствения ключ и лимитите на акаунта.

`session-candidates.js` проверява десетте нови кандидата и поправения дневен EMA: приключилите сделки не се променят от бъдещи свещи, дневните изходи са в същия ден, а рискът се проверява и при гап. Проверява се и проследяването на архивен модел след обичайния 14-дневен прозорец. `observation-risk-costs.js` покрива суапа през лятното време, частичния обем, първоначалните записи на журнала, групирането и личния риск. `maintenance.php` прави временен сайт за проверка на резервните копия, възстановяването и файловете на версията. `login.php` проверява ограничението на грешните пароли. `prices.php` проверява пълните часови свещи, размера на заявката след прекъсване, пазарните часове по Ню Йорк и откриването на дупки. `entry.js` проверява вида поръчка спрямо цената, съветите „може/изчакай/късно/към стопа“, чакащите поръчки, праговете и измерването на вход по-късно върху сделки, сметнати на ръка.

Браузърната проверка изисква `DocumentRoot` в избрания runtime да сочи към това работно копие. При различен каталог тестът спира преди стартиране на Apache. Използвай `TP24_TEST_RUNTIME` за отделен runtime; това пази другите работни копия от тестови записи.

След промяна на кодов файл или вградения каталог обнови списъка на пакета с `python tests/release.py --write`. Пълното преизчисляване на вградените резултати е `node tests/catalog-report.js --write`; без `--write` командата само сравнява. Това са инструменти за разработка, без връзка с доставчици и без Node.js на хостинга.

## Къде е логиката

- `fx-core.js`, `fx-series.js`, `fx-indicators.js` — свещи, време и индикатори.
- `fx-backtest.js`, `fx-engine.js` — изпълнение, статистика и ценови сигнали.
- `fx-strategies.js`, `fx-library.js`, `fx-candidates.js` — правила на стратегиите.
- `fx-book-candidates.js` — седемте нови идеи с фиксирани собствени правила и версии.
- `fx-revisions.js`, `fx-evaluation.js` — преработки, сравнения, оценки по инструменти и подбор на модели.
- `fx-catalog.js`, `data/catalog.json` — архив, версии и вградени резултати, които се сливат с работните данни.
- `fx-new-candidates.js` — десетте кандидата с предварително описани правила в `docs/new-candidates.md`.
- `fx-costs.js`, `api/state.php` — разходи и публично четене на профила, без секрети.
- `fx-observed.js`, `observed-ui.js` — журнал на наблюдаваните в браузъра сигнали.
- `fx-signal-tools.js`, `notifications.js` — групиране, състояние на входа и известия при отворен сайт.
- `fx-entry.js`, `entry-ui.js` — вход след сигнала, видове поръчки, бланка за поръчката и измерване по историята.
- `fx-chart.js`, `chart-ui.js` — графиката с модела и страницата на инструмента; `assets/vendor/lightweight-charts/` — TradingView Lightweight Charts™ 5.2.1 без промени, с лиценза и NOTICE.
- `panel-layout.js`, `assets/workspace.css` — местене, запазване на реда и мобилна подредба. Връщането на подредбата не изчиства чужди ключове в localStorage.
- `api/maintenance.php`, `maintenance-ui.js` — сървърни копия, възстановяване и проверка на файловете.
- `fx-builder.js`, `lab.js`, `fx-worker.js` — конструктор и тестове.
- `api/workspace.php`, `api/save.php` — чернови, версии и публикуване.
- `fx-news.js` — преводи и предварително написани обяснения на събитията.
- `fx-calendar.js` — избор на дата, предстоящи/минали събития и граждански дни по Europe/Sofia.
- `puls.js`, `api/puls.php`, `api/puls-lib.php` — разговор, дневен обзор, Groq и защитен кеш.
- `risk.js` — личен дневник и лимити на риска.

`data/private/` съдържа личните чернови и е недостъпна през HTTP. Дневникът на посетителя е само в неговия браузър. Генерирани ZIP архиви, временни отчети и локални настройки не се добавят в Git. Подробните отчети от предишния преглед остават достъпни в [историята на изследването](strategies.md#архив-на-проверката).

## Ако използваш nginx

`.htaccess` не се изпълнява от nginx. Добави еквивалентните ограничения преди общото PHP правило:

```nginx
location ^~ /data/private/ { deny all; }
location ^~ /tests/ { deny all; }
location ~ (^|/)\. { deny all; }
location ~ ^/api/(?!(?:cron|save|puls|state)\.php$) { deny all; }
location ~ ^/(README|AGENTS|CHANGELOG)\.md$ { deny all; }
location ~ ^/data/.*\.(php|phtml|phar|lock|tmp[0-9]*)$ { deny all; }
```

Провери реда спрямо останалите location правила. Папката `data/` трябва да е достъпна за запис от PHP, но да не допуска изпълнение на качени скриптове.


## Пакет за обновяване

След проверките и обновяване на `release.json`:

```sh
python tests/package.py --output /tmp/TradePulse24-5.2.1-update.zip
python tests/update.py /tmp/TradePulse24-5.2.1-update.zip
```

Пакетът включва runtime файловете от списъка на версията и документацията. Тестът за обновяване пази примерни конфигурации, всички 24 ценови файла, работните резултати и частните копия. ZIP и SHA-256 файлът се публикуват отделно от основния клон с кода.

`workspace.py` проверява реално местене с мишка, клавиатура и бутони, ред след презареждане, четирите периода на преглед, неизменни сигнални нива, историята от локални JSON и размери от 320 до 1440 пиксела. `chart-context.js` покрива времето на маркерите при друг период и модела с вход преди изтекъл срок при стари данни.

Проверката в `workspace.py` включва актуални цени при отказ на резервен доставчик, стари и липсващи цени, безопасни публични съобщения и стари препратки към доставчици в кеша на Пулс. Техническите грешки остават в административните проверки; публичният интерфейс показва състоянието на данните.
