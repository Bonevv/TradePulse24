# Календар през JB-News

Worker поддържа **MQL5 календара през JB-News (JBlanked)** като основен източник. Директният ForexFactory фийд остава резервен. API ключът е в Cloudflare; посетителите четат само общия кеш.

Официалната [библиотека JB-News](https://github.com/jblanked/JB-News) описва безплатен достъп с най-много една заявка на пет минути. Наличността и условията за конкретния акаунт се проверяват с неговия ключ. Локалните тестове използват примерни отговори и не доказват налична квота в чужд акаунт.

## Включване

1. Вземи API ключ от [профила в JBlanked](https://www.jblanked.com/profile/).
2. Отвори Cloudflare → твоя Worker → Settings → Variables and secrets.
3. Добави **Secret** с име `JBLANKED_API_KEY` и стойност ключа. Избери Production и публикувай настройките. Не го записвай в GitHub, PHP конфигурацията или build variables.
4. Изчакай успешно изграждане на актуалния Worker от GitHub.
5. Отвори Worker адреса с `/admin`, въведи отделния `FEED_ADMIN_TOKEN` и натисни **„Провери календара“**.

При успех в отговора има `ok: true`, `calendar.source: "jbnews"` и нов `calendar.last_success`. Ако е използван резервът, source е `forexfactory`. `jbnews_configured: true` означава само, че ключът е зададен; не доказва успешна заявка. Провери полето `providers.jbnews.problem`.

Тази промяна е само в Worker. PHP интерфейсът от 5.3 насам чете същия формат на котировки и събития. Не е нужно повторно зареждане на историята или ново качване на PHP файлове за връзката към календара. Отделните поправки на PHP конфигурацията се инсталират по собствените им указания.

## Часова зона

Доставчикът може да върне ISO час с `Z` или числов UTC offset. Той се приема директно. Ако датата е текст без часова зона, например `2026.11.09 15:30:00`, Worker връща **`timezone_required`** и не публикува час по предположение.

В административния отговор има до пет примерни заглавия, валути и дати, за да се провери зоната спрямо доставчика. Те не съдържат API ключа.

След потвърждение на зоната добави обикновена **runtime Variable**, не Secret:

```text
JBLANKED_TIMEZONE
```

Стойността е IANA зона на **входните дати от доставчика**, а не зоната, в която искаш да гледаш сайта. Примери: `UTC`; `Etc/GMT-3` за фиксирано UTC+3; `Europe/Sofia` само ако входните дати действително следват софийското лятно/зимно време. Не избирай зона само защото живееш в България. Официалната библиотека има ръчна offset настройка; тя не е достатъчна сама по себе си да потвърди текущите часове на конкретен отговор.

Публикувай променливата и провери отново след минималната петминутна пауза на API. `keep_vars` запазва runtime променливите при следващи публикувания на кода. Сайтът показва вече нормализираните UTC времена по Europe/Sofia.

Нееднозначен или несъществуващ местен час при смяна на лятното време се отхвърля. Не променяй часовете на събитията ръчно само за да изчезне предупреждението.

## Обновяване и резерв

С JB-News се проверява през около 15 минути, независимо от нощния график за цените. Без ключ остава почасовият ForexFactory календар. Ръчният бутон спазва общата пауза от поне пет минути за JB-News и час за ForexFactory. Броячите и блокировките се пазят в координатора и не се нулират с презареждане на страницата.

При отказ на основния източник се опитва резервът. При отказ и на двата последните събития остават с оригиналния час на успешно получаване. Неуспешна заявка не подновява този час. Ключове, HTTP подробности, паузи и примерни дати се показват само след административно удостоверяване.

Записват се име, валута, дата, важност, прогноза, предишна и обявена стойност. Бъдещ резултат остава неизвестен; обявена нула се запазва. HTML, празни или невалидни отговори не заменят работещия календар. Точната важност и часът трябва да се потвърдят при първото включване с реални събития.

## Кодове при проверката

| Код | Значение |
|---|---|
| `access_denied` | API отказва достъп: провери ключа и достъпа до календара в акаунта |
| `rate_limited` | Изчакай паузата; не натискай многократно |
| `timezone_required` | Часовете нямат зона и трябва потвърдена `JBLANKED_TIMEZONE` |
| `timezone_invalid` | Зоната не е разпозната |
| `invalid_json` | Получен е невалиден JSON, например HTML страница |
| `invalid_calendar`, `invalid_date`, `unknown_impact` | Отговорът не покрива очакваната схема |
| `wrong_calendar_week` | Събитията са извън допустимия близък период |
| `unavailable` | Заявката не завършва успешно |

Ако `source` е ForexFactory, докато JB-News има проблем, резервът работи. Това не доказва, че основният източник вече е настроен.
